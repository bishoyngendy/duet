# Host step: break the plan into tasks
Produce an ordered task DAG (ids T001, T002, …) that implements the final plan. Each task must be a self-contained brief an engineer can implement and a reviewer can verify in one pass: clear description, depends_on, files_in_scope (globs, including test files), acceptance checks, and a test_command when a targeted test exists. Organise them the Spec Kit way (input `tasks_template`): phase "setup" (shared infrastructure), "foundational" (blocking prerequisites every story needs), then "story" tasks grouped per user story in priority order with `story` set (US1 first — the MVP), then "polish". Each story's tasks should deliver that story independently testable. Tasks with no dependency between them and non-overlapping files_in_scope are implemented concurrently, so keep files_in_scope precise. Prefer 3-10 tasks for a typical feature; each should leave the code building and tests passing.
